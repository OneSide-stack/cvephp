# Guest image provisioning

The repository intentionally excludes ISOs and other large generated media. `public/lab-assets/manifest.json` starts with unavailable image entries until the artifacts are installed. The UI displays this state and refuses to boot a missing required image.

After installing or building media:

```sh
npm run assets:runtime
node scripts/generate-asset-manifest.mjs
npm run assets:verify
```

Never edit a digest to make a changed image pass. Rebuild the manifest from the actual bytes, review the change, and treat the resulting image as a new artifact.

## Attacker build

`image-build/build-attacker.sh`:

1. Downloads the immutable Tiny Core 11.0 base image and verifies its SHA-256.
2. Resolves the TinyCore package dependency set, verifies publisher MD5 files where supplied, and writes a SHA-256 inventory.
3. Extracts the ISO and `core.gz` in an Alpine build container.
4. Installs the real guest boot/network scripts, serial console, RangeProxy, research harness, Dillo configuration, and notes.
5. Adds the offline `.tcz` packages to `cde/onboot.lst`.
6. Rebuilds the initramfs and bootable ISO with xorriso.

The 11.0 publisher directory now retains 11.1 rather than the original 11.0 ISO. To avoid silently changing the lab profile, the script uses this immutable mirror:

```text
https://api.github.com/repos/alizafarbati/WebLinux/git/blobs/45166e33208626dc6074f20ba0dbd8824d113358
(with HTTP Accept: application/vnd.github.raw+json; blob pinned by commit 9be9b5f435281dc7d78467131dbc1b77e10a8198)
SHA-256: 778fc3788d9df3de72970827968b2b195aca827401db6f6f9cbdb737d4300bda
Size: 19,922,944 bytes
```

This is a third-party mirror of base media, authenticated by the recorded digest. It is not an independent security audit or proof that the graphical stack works under v86; that requires a real boot test.

## Target build

`image-build/build-target.sh <version> <output-name>`:

1. Downloads the official PHP source tag from GitHub and checks the version-specific SHA-256 in `image-build/target/php-source.sha256`.
2. Downloads the official Alpine 3.22.1 x86 standard ISO and checks the publisher's SHA-256 file.
3. Uses `image-build/target/Dockerfile` to compile PHP for 32-bit x86 with Apache's `apxs2`, prefork, session support, upload progress, the pinned `php.ini`, and the custom web application.
4. Exports the actual Alpine root filesystem, adds OpenRC/network/service scripts, and packages it as the initramfs with the official Alpine kernel/boot files.
5. Rebuilds a bootable ISO and emits its digest.

The target is not PHP-FPM, the PHP built-in server, a JavaScript HTTP implementation, or a WordPress image. `wp-login.php` is only a WordPress-style route in the custom training application.

## GitHub Actions artifact

The **Build reproducible guest images** workflow runs the same build scripts, generates/verifies the manifest, and uploads `cyber-range-guest-images`. Download the artifact from a successful run, preserve its `public/` paths when extracting, and run `npm run assets:verify` locally. An artifact's existence proves only that the CI build and checksum steps completed; it does not prove that v86 can boot it or that the guests can communicate.

## Offline behavior

At lab start the controller fetches only same-origin `/v86/` and `/lab-assets/` paths, checks exact byte counts and SHA-256, and stores verified assets in IndexedDB when quota permits. The service worker caches the application shell, not a fake guest or an unverified image. After a complete successful cache, the shell and verified media can be used without lab-start Internet access. Browser storage eviction, quota, or a first-time offline visit can still require the local static server/media.

## Common failures

- **HTTP 404 while downloading TinyCore 11.0:** use the committed immutable mirror and digest; do not rename a 11.1 image to 11.0.
- **Docker cannot execute 32-bit binaries:** enable the host's x86/32-bit Docker support or use the CI builder. Do not replace the target with an amd64 image and claim equivalent offsets.
- **`libphp.so` missing or `httpd -t` fails:** inspect the Docker build; the target is deliberately mod_php/prefork and cannot be substituted with FPM.
- **Manifest says unavailable:** regenerate it after placing files in `public/lab-assets/`; the manifest is not a download instruction.
- **SHA-256/byte-length mismatch:** remove the corrupted file and restore the exact artifact. Boot is refused by design.
- **No guest display or serial prompt:** inspect actual v86 output and ISO boot configuration. A successful ISO checksum is not a boot test.
